# نشر خُطى — دليل التنفيذ

## الخلاصة أولًا

النشر صار ممكنًا **بلا SSH**: لوحة Docker في Hostinger تستقبل ملف compose
وتُشغّله. وقد فُحص الخادم، وعُرفت إعدادات Traefik عليه، وجُهّز الملف بها.

بقي أمران يحتاجان يدك، ولا ثالث لهما:

| # | الأمر | السبب |
|---|---|---|
| ١ | **سجلّ DNS واحد** | واجهة Hostinger ترفض الكتابة في زون `b14facilities.com` برسالة «Customer does not own» رغم أن النطاق في محفظتك وخوادم أسمائه هي `ns1/ns2.dns-parking.com` أي Hostinger نفسها. خلل صلاحية في الواجهة، والزون يُحرَّر من hPanel بلا مشكلة. |
| ٢ | **مستودع Git للشيفرة** | Docker على الخادم يبني الصورة من رابط مستودع. بيئة العمل لا تصل إلى GitHub بصلاحية كتابة، فلا أستطيع إنشاء المستودع ولا الدفع إليه. |

## حالة الخادم كما فُحصت

| | |
|---|---|
| الخادم | `srv1979813.hstgr.cloud` · `187.53.140.62` · KVM 2 · معالجان · ٨ جيجابايت · ١٠٠ جيجابايت |
| النظام | Ubuntu 24.04 مع Docker و Traefik |
| الموقع | **كوالالمبور، ماليزيا** |
| يعمل عليه الآن | مشروعان: `traefik` و `ticketing-system` (حاوية `b14helpdesk-app`، سليمة منذ ثلاثة أيام) |
| شبكة Traefik | `traefik-proxy` |
| مدخل HTTPS | `websecure` |
| مُصدِر الشهادات | `letsencrypt` |
| استهلاك الذاكرة الحالي | أقلّ من ٢٪ من ٨ جيجابايت — متّسع واسع |

النشر يضيف مشروعًا ثالثًا باسم `khuta` ينضمّ إلى شبكة Traefik القائمة. لا يعدّل
Traefik، ولا يمسّ `ticketing-system`، ولا يفتح منفذًا على الإنترنت بنفسه.

### ملاحظة الموقع الجغرافي — تُقرأ قبل أي قرار إنتاجي

لا تملك Hostinger مركز بيانات في الإمارات ولا في الشرق الأوسط؛ أقربها مومباي،
وهذا الخادم في ماليزيا. مقبول لنموذج إثبات إمكانية ببيانات تجريبية، وهو ما
نبنيه. **غير مقبول لبيانات موظفي البلدية الحقيقية** — قرار سيادي يسبق أي إطلاق.
البديلان: استضافة داخل الإمارات، أو المسار الأول في العرض (التسليم إلى قسم تقنية
المعلومات في البلدية ليعمل داخل حساب Microsoft الخاص بهم).

### لماذا خادم وليس الاستضافة المشتركة

الاستضافة المشتركة تقدّم MySQL فقط، وأمان المنصّة مبنيّ على خصائص PostgreSQL:
عزل الجهات بـ Row-Level Security، وحجب عمود مفتاح الإجابة عن دور التطبيق
بالصلاحيات، والتصحيح داخل دوالّ مؤمَّنة. النقل إلى MySQL يُلغي الإنفاذ نفسه
ويستبدل به انضباط الكود — وهو ما يرفضه العرض الفني.

## الخطوة ١ — سجلّ DNS

في hPanel ← Domains ← `b14facilities.com` ← DNS / Nameservers:

| النوع | الاسم | القيمة | TTL |
|---|---|---|---|
| A | `khuta` | `187.53.140.62` | 3600 |

سجلّ واحد فقط. لا wildcard، ولا تعديل على سجلّ قائم، ولا سجلّ بريد.

الوضع الحالي للزون كما قرأته من الخارج قبل أي تغيير، للمقارنة بعده:
الجذر على `88.223.87.15` و `145.223.124.135`، وثلاثة سجلّات TXT فيها
`v=spf1 include:_spf.google.com ~all`، و `khuta.b14facilities.com` غير موجود
إطلاقًا (NXDOMAIN) — فإضافته لا تزاحم شيئًا.

## الخطوة ٢ — المستودع

ارفع `khuta-platform-source.tar.gz` إلى مستودع Git (خاصّ أو عام، كما ترى)، ثم
أعطني رابطه. ما يحتاجه Docker هو رابط يستطيع استنساخه، مثل:

```
https://github.com/<الحساب>/khuta-platform.git
```

لمستودع خاصّ، يُمرَّر الرمز في المتغيّرات لا في ملف compose:

```
SOURCE_REPO=https://x-access-token:<TOKEN>@github.com/<الحساب>/khuta-platform.git
```

## الخطوة ٣ — النشر

من لوحة Docker في Hostinger (أو أتولّاه أنا عبر الواجهة البرمجية): مشروع جديد
باسم `khuta`، محتواه ملفّ `deploy/docker-compose.hostinger.yml`، ومتغيّراته:

```
KHUTA_HOST=khuta.b14facilities.com
SOURCE_REPO=<رابط المستودع>
TRAEFIK_NETWORK=traefik-proxy
CERT_RESOLVER=letsencrypt
POSTGRES_PASSWORD=<عشوائية>
APP_DB_PASSWORD=<عشوائية>
KHUTA_SECRET=<عشوائية ٦٤ خانة>
KHUTA_MFA_KEY=<عشوائية ٦٤ خانة>
KHUTA_DEFAULT_TENANT=alain
```

لتوليد القيم: `openssl rand -hex 32`

> `KHUTA_MFA_KEY` يفكّ تشفير أسرار المصادقة الثنائية. فقدانه يعني أن كل
> المستخدمين يحتاجون إعادة تسجيل تطبيق المصادقة. احفظه حيث تُحفظ المفاتيح.

ما يحدث عند التشغيل: Docker يستنسخ المستودع ويبني الصورة، ثم تُقلع قاعدة
البيانات، ثم تعمل حاوية `migrate` مرة واحدة فتطبّق ملفات `db/` بالترتيب وتضبط
كلمة مرور دور التطبيق، ثم يُقلع التطبيق وينضمّ إلى Traefik. وعند أول زيارة
يُصدر Traefik شهادة Let's Encrypt تلقائيًا.

الترحيل مسجَّل في جدول `schema_migration`، فإعادة التشغيل لا تعيد تطبيق شيء —
مُختبَر: سبعة ملفات في التشغيل الأول، وصفر في الثاني.

## بعد النشر

```
المتعلّم التجريبي:  docker compose exec app node scripts/seed_demo_user.js
ملفات الدروس:      docker compose cp media/. app:/app/media/
فحص القواعد:       docker compose exec app node test/totp.test.js
```

الأمر الأخير وأشباهه تُشغَّل من اللوحة أيضًا. وفحص القواعد على قاعدة حيّة
(`db/003_verify.sql`) يحتاج عميل psql، فيُشغَّل من حاوية قاعدة البيانات.

## النسخة الاحتياطية والاسترجاع

```
نسخة احتياطية:  docker compose exec -T db pg_dump -U khuta -Fc khuta > khuta-$(date +%F).dump
إيقاف:          docker compose down          (البيانات باقية)
إزالة كاملة:     docker compose down -v        (تحذف قاعدة البيانات والوسائط)
```

ولا أثر لأيٍّ منها على `traefik` ولا على `ticketing-system`. ويبقى حذف سجلّ DNS
خطوة يدوية في hPanel.

## النشر على خادم تملك عليه SSH

`deploy/docker-compose.yml` و `deploy/deploy.sh` هما المسار الآخر: يحقنان ملفات
SQL في حاوية قاعدة البيانات مباشرة ويبنيان من الشيفرة المحلية، فلا يحتاجان
مستودعًا.
